## 📚 Theory — IIS Advanced Configuration

### 1. DNS Records for Website Hosting

DNS records allow clients to access websites using hostnames instead of entering an IP address directly.

- **Host (A) record:** Maps a hostname to an IPv4 address.
- **Alias (CNAME) record:** Maps an alias to another canonical hostname.

In this lab, the `travel.com` Forward Lookup Zone contains a Host (A) record named `DC-01` pointing to `10.0.0.1`, and a `www` CNAME record targeting `DC-01.example.com`.

### 2. IIS Website Bindings and Host Names

An IIS binding identifies how a website receives requests. It can include an IP address, port, protocol, and host name.

When multiple websites share an IP address and port, IIS can use the HTTP host name supplied by the client to select the appropriate website. HTTP commonly uses port **80**, while HTTPS commonly uses port **443**.

### 3. HTTP Redirection

HTTP Redirection instructs a browser to request another URL. In this lab, requests to the existing `infozak.com` website are redirected to the exact destination:

```text
http://www.travel.com
```

The **Redirect all requests to exact destination (instead of relative to destination)** option ensures that the configured destination is used as the redirect target.

### 4. Self-Signed SSL Certificates

An SSL/TLS certificate is used by HTTPS to help authenticate a server and establish an encrypted connection. A self-signed certificate is generated by the server itself rather than being issued by a publicly trusted Certificate Authority.

The certificate created in this lab is named `example-cert` and is stored in the **Web Hosting** certificate store. Because it is self-signed, a browser or client that does not trust it may display a certificate warning even when the HTTPS connection is functioning.

### 5. HTTPS Bindings and Server Name Indication (SNI)

An HTTPS binding associates a website with an IP address, port, host name, and SSL certificate. Server Name Indication (SNI) allows IIS to use the hostname supplied during the TLS handshake to select the appropriate certificate when multiple HTTPS websites share an IP address.

In this lab, the `travel.com` website uses HTTPS on port **443**, the host name `www.travel.com`, and the `example-cert` certificate, with SNI enabled.

### 6. IP-Based Website Access

An IIS binding can be configured without a host name. When a request is sent directly to the server IP address, IIS uses the matching IP-and-port binding to determine which website receives the request.

In the final exercise, the host name is removed from the existing `infozak.com` HTTP binding, leaving the IP address `10.0.0.1` and port `80`. The website is then tested from `CLIENT-01` using the server IP address.

## ⚙️ Lab Configuration

### Step 1 — Create the travel.com DNS Forward Lookup Zone

1. Sign in to `DC-01`.
2. Open **Server Manager → Tools → DNS** to launch DNS Manager.
3. Expand the DNS server.
4. Right-click **Forward Lookup Zones** and select **New Zone**.
5. Complete the New Zone Wizard and name the new Forward Lookup Zone:

   `travel.com`

6. Finish the wizard and confirm that the `travel.com` zone appears under **Forward Lookup Zones**.

### Step 2 — Create the Host (A) and Alias (CNAME) Records

1. Expand the `travel.com` Forward Lookup Zone.
2. Right-click the zone and select **New Host (A or AAAA)**.
3. Create the Host (A) record using the following details:

| Setting | Value |
|---|---|
| Name | `DC-01` |
| IP address | `10.0.0.1` |

4. Click **Add Host**.
5. Right-click the `travel.com` zone and select **New Alias (CNAME)**.
6. Configure the alias as follows:

| Setting | Value |
|---|---|
| Alias name | `www` |
| Fully qualified domain name (FQDN) for target host | `DC-01.example.com` |

7. Click **OK**.
8. Confirm that the zone contains the `DC-01` Host (A) record and the `www` Alias (CNAME) record.

### Step 3 — Create the travel.com Website in IIS

1. Open **Server Manager → Tools → Internet Information Services (IIS) Manager**.
2. Expand `DC-01 (EXAMPLE\Administrator)`.
3. Right-click **Sites** and select **Add Website**.
4. Configure the new website as follows:

| Setting | Value |
|---|---|
| Site name | `travel.com` |
| Physical path | The folder containing the Travel website files |
| IP address | `10.0.0.1` |
| Port | `80` |
| Type | `http` |
| Host name | `www.travel.com` |

5. Click **OK** to create the website.
6. Confirm that `travel.com` appears under **Sites** in IIS Manager.

### Step 4 — Add travel.html as the Default Document

1. Select the `travel.com` website in IIS Manager.
2. Double-click **Default Document**.
3. Right-click the white space in the Default Document list and select **Add**.
4. Enter the filename:

   `travel.html`

5. Click **OK**.
6. Confirm that `travel.html` appears in the Default Document list.

### Step 5 — Configure HTTP Redirection on infozak.com

1. In IIS Manager, select the existing `infozak.com` website.
2. Double-click **HTTP Redirection**.
3. Check **Redirect requests to this destination**.
4. Enter the exact destination:

   `http://www.travel.com`

5. Under **Redirection Behavior**, check **Redirect all requests to exact destination (instead of relative to destination)**.
6. In the right-hand **Actions** pane, click **Apply**.
7. Confirm that the redirection configuration is applied to the `infozak.com` website.

### Step 6 — Verify the HTTP Redirection

1. Open Microsoft Edge on `DC-01`.
2. Browse to the existing Infozak website:

   `http://www.infozak.com`

3. Confirm that the browser redirects to:

   `http://www.travel.com`

4. Confirm that the Travel webpage opens successfully after redirection.

### Step 7 — Create a Self-Signed SSL Certificate

1. In IIS Manager, select the server node:

   `DC-01 (EXAMPLE\Administrator)`

2. Double-click **Server Certificates**.
3. In the right-hand **Actions** pane, click **Create Self-Signed Certificate**.
4. Enter the certificate name:

   `example-cert`

5. In **Select a certificate store for the new certificate**, choose:

   `Web Hosting`

6. Click **OK**.
7. Confirm that `example-cert` appears in the Server Certificates list.
8. Double-click the certificate to inspect its details and certificate hashes.

### Step 8 — Add an HTTPS Binding to the travel.com Website

1. In IIS Manager, select the `travel.com` website.
2. In the right-hand **Actions** pane, click **Bindings**.
3. Click **Add**.
4. Configure the new binding as follows:

| Setting | Value |
|---|---|
| Type | `https` |
| IP address | `10.0.0.1` |
| Port | `443` |
| Host name | `www.travel.com` |
| Require Server Name Indication | Checked |
| SSL certificate | `example-cert` |

5. Confirm that the HTTPS port is `443`.
6. Click **OK** to add the binding.
7. Close the Site Bindings window.

### Step 10 — Modify the infozak.com HTTP Binding

1. Return to IIS Manager and select the existing `infozak.com` website.
2. In the right-hand **Actions** pane, click **Bindings**.
3. Select the existing binding configured with:
   - Type: `http`
   - IP address: `10.0.0.1`
   - Port: `80`
   - Host name: `www.infozak.com`
4. Click **Edit**.
5. Remove the host name `www.infozak.com`.
6. Leave the IP address as `10.0.0.1` and the port as `80`.
7. Click **OK** and close the Site Bindings window.

## 🌍 Real-World Use Case

Organizations often host multiple internal websites on a Windows Server using IIS. DNS records and host-name bindings allow users to access each website through a recognizable name, while HTTP redirection can guide users from an old website address to a new destination.

HTTPS protects data exchanged between browsers and web servers. IIS bindings and SNI help administrators host multiple HTTPS websites on shared server addresses while selecting the appropriate certificate for each hostname. IP-based bindings can also be useful for default websites or services that must respond to requests made directly to a server address.
